## 它能做什么

鼠标移到刘海上，刘海会弹一下、变大一圈（用 Force Touch 触控板时还会轻轻震一下）；点一下，它才「长大」成一个黑色的小面板；移开后又缩回去，和硬件刘海融为一体。拖着文件靠近刘海，不用碰到屏幕顶端，它就会直接展开到「文件」页（拖到屏幕最上沿时 macOS 会打开调度中心）。

目前内置的功能：

| 功能 | 说明 |
|---|---|
| 🎧 AirPods | 连上 AirPods 时，刘海左侧短暂显示耳机图标、右侧显示电量。连接期间，展开面板里刘海左侧、紧挨着刘海的位置会多出一个耳机标签页，可以看到左右耳和充电盒的电量，调节耳机音量和降噪模式（降噪 / 通透 / 自适应，视型号而定）。声音切换回 Mac 自带扬声器时（比如 AirPods 断开），刘海两侧也会短暂显示电脑图标和当前音量，这部分不需要蓝牙权限。系统自带的连接提示无法隐藏，仍会出现。需要「蓝牙」权限；降噪模式用的是系统未公开的接口，系统更新后可能失效 |
| 🏠 主页 | 展开后的主页，由几个模块从左到右排成一行，目前有时间、天气、日历、笔记和提醒事项五个模块。时间最窄时是一个正方形，显示时:分和日期，加宽后显示到秒，点一下打开计时器（见下）；天气最窄占整行的三分之一，上面是当前天气、下面是未来三小时，加宽后左边是当前天气、右边随宽度显示更多小时。展开后的岛和模块一样宽，两边不留黑边，最宽随模块数增加：一个模块时 520 点，第二、第三个模块各多 120 点，第四个只多 80 点，免得太宽，四个时最宽 840 点；模块加起来不到 520 点时岛保持 520 点。切到其他标签页时恢复原来的宽度，切换时带动画过渡。在「设置…」的「主页」页里可以选择放哪些模块（最多四个）；预览里拖动两侧边缘可以整体等比缩放所有模块，拖动模块之间的分隔线调整相邻两个模块的长度，长按模块可以拖动换位置，点模块右上角的 ✕ 移除，缩放到最长或最短时会有提示 |
| ⏱️ 计时器 | 倒计时。点主页上的时间模块打开计时器面板：左边是时长，用「−」「+」按分钟调（1–180 分钟），调好后点「开始」；右边是 1、3、5、10、15、25、30 分钟和 1 小时几个常用时长，点一下直接开始。也可以在刘海的右键菜单「计时器」里直接选一个时长开始，「自定义…」打开同一个面板。计时期间，展开面板里刘海右侧、紧挨着刘海的位置会多出一个计时器标签页，标签按钮是一圈随剩余时间缩短的橙色进度环，点开可以看到剩余时间，暂停 / 继续、加 1 分钟或取消；从面板开始计时后会直接切到这里，点时间模块也会打开它。主页上的时间模块同时换成倒计时和结束时间。岛收起时，刚开始的 5 秒里刘海左侧紧挨着刘海是一圈橙色圆环、右侧是剩余时间；之后两侧收回，岛比刘海稍大一圈，边缘亮起一圈橙色光带，光带的长短表示剩余时间，开始时绕满左、下、右三边，随时间从左往右缩短，暂停时变暗，比「正在播放」优先显示。展开刘海时，光带沿边缘收进右上角；收起时，再从右上角沿着收拢的边缘伸出来。有别的提醒盖在上面时也一样。点刘海两侧会打开计时器标签页，右键菜单里也能暂停、加时或取消。时间到了，刘海两侧显示晃动的铃铛和「时间到」，并响几声提示音（最多 5 次），点一下停止，也可以「再来一次」。上次开始的时长会记下来，作为下次的默认时长。同一时间只能有一个计时器，只保存在内存里，退出 Notch 后就没了 |
| 🌤️ 天气 | 主页上的天气模块：当前气温、天气和今天的最高 / 最低气温，以及接下来几个小时的预报，温度单位跟随系统设置。一天分成三个时段，每个时段可以显示今日天气、未来几小时或明日天气（默认 5–10 点今日、10–19 点未来几小时、19 点到次日 5 点明日），在「设置…」的「天气」页里拖动 24 小时圆环调整。需要「定位」权限，只用大致位置；数据来自 [Open-Meteo](https://open-meteo.com)，请求里只带精确到小数点后两位的经纬度；顺便取回当地的日出日落时间，用来点亮岛的边缘（见下文「光影与色彩」）。只在展开面板时更新，15 分钟最多一次 |
| 📅 日历 | 主页上的日历模块：按天列出从今天起几天内的日程（默认 3 天，可以设为 1–14 天，包括今天）。每天的全天日程排在最前面，正在进行的日程标为「进行中」，已经结束的不再显示；卡片按下一个日程所在日历的颜色着色。日程有两个来源：一是 macOS 的「日历」App，包括在「系统设置 → 互联网账户」里添加的 iCloud、Google、Exchange 等账户，可以逐个选择显示哪些日历；二是订阅链接，比如 Google 日历的「iCal 格式的私密地址」或 Outlook 的「发布日历」ICS 链接，只读不写。卡片右上角有「全部 / 本机 / 云端」切换，可以只看「日历」App 或只看订阅链接里的日程。这些都在「设置…」的「日历」页里设置，那里也能切换显示哪种来源。读取「日历」App 需要「日历」权限，只用订阅链接的话可以不给；订阅链接相当于密码，只保存在本机，下载的日历不写入磁盘缓存，展开面板时更新，15 分钟最多一次。日程快开始时，刘海两侧会提醒：提前多久在「设置…」的「日历」页里选（不提醒、开始时，或提前 1、5、10、15、30 分钟、1 小时，默认提前 5 分钟）；到了提前的时间弹一次「5 分钟后」，开始时再弹一次「现在开始」，几个日程同时到时合在一起提醒；到点时刘海如果正展开着，提醒会等收起后再完整显示，日程已经结束的就不再显示。提醒只看设置里勾选显示的日历和打开的订阅链接，不管卡片上的「全部 / 本机 / 云端」切换，全天日程不提醒，日历模块不放在主页上也会提醒。点一下提醒打开日程详情；日程里有 Zoom、Google Meet、Teams、腾讯会议、飞书、钉钉或 Webex 的会议链接时，可以直接点「加入会议」。「日历」App 自己的提醒照常出现（打开通知功能时也会显示在岛上），不想重复可以关掉其中一个。打开提醒后，订阅链接在岛收起时也每 30 分钟更新一次 |
| 📝 笔记 | 随手写笔记和随笔。展开面板里刘海右侧、电池旁边有一个笔记标签页：左边是笔记列表，最新建的在最上面，右键可以删除；右边直接写。也可以把笔记模块放到主页上，模块较窄时只显示正文，上方用左右箭头在笔记之间切换、「+」新建；主页上有笔记模块时，点笔记标签页，模块会放大成标签页，切回主页时再缩回原处。点一下正文就能打字，当前使用的 App 不会被切走；打字时鼠标移出岛也不会收起，点别处或按 Esc 结束编辑，岛收起后键盘回到原来的 App。边写边自动保存，空白的笔记切走后自动删除；笔记只保存在这台 Mac 上（`~/Library/Application Support/io.github.hyperspaceft.notch/Notes.json`） |
| ✅ 提醒事项 | 主页上的提醒事项模块：「提醒事项」App 里还没完成的待办，在「设置…」的「主页」页里加到主页上，没有单独的标签页。最上面一行直接输入，回车新建一条，放进「提醒事项」App 的默认列表；点左边的圆圈勾掉，一秒半内再点一下可以撤销；右键可以删除，或在「提醒事项」App 中打开。有截止时间的排在前面，最早的在最上面，逾期的时间标成红色；没有截止时间的排在后面，最新建的在前。打字方式和笔记一样，当前使用的 App 不会被切走，按 Esc 结束输入。改动直接写进「提醒事项」App，也会通过 iCloud 同步到其他设备。需要「提醒事项」权限，第一次点卡片上的「允许」时才会请求 |
| 📂 文件 | 左边是隔空投送区，把文件拖进去即可用 AirDrop 发送；右边是文件暂存区，拖进来的文件可以再拖出去或右键「拷贝」后粘贴。暂存区里按住 Command 点按可以多选，按住 Shift 点按选中一段，按住 Shift 拖动可以框选（从空白处拖动也能框选），在暂存区里点一下后按 Command-A 全选；拖出、拷贝、在访达中显示和移除都会作用于所有选中的文件。打开「粘贴后自动删除文件」后，文件被拖出或粘贴后会自动从暂存区移除（不会删除原文件） |
| 🔋 电池 | 插上电源时，刘海左侧短暂弹出绿色的充电电池图标、右侧显示电量百分比，拔掉电源时也会提示；展开后刘海右侧的电池图标随电量变化，点开可以看到剩余时间和电池健康（最大容量、循环次数） |
| 🔊 音量与亮度 | 按音量键或亮度键时，用刘海两侧的提示代替系统自带的：左边是图标，右边的圆环显示当前音量或亮度；按住 Option + Shift 可以更细地调节。需要「辅助功能」权限（见下面的安装步骤），不想用可以在「设置…」的「灵动岛」页里关掉 |
| 🎵 正在播放 | 系统「正在播放」里有内容时（浏览器里的 YouTube / 哔哩哔哩、「音乐」、Spotify 等），刘海向两侧稍稍展开，两边各只多出一小段：左边紧挨着刘海的是封面（没有封面时显示播放器的图标），换歌时像翻唱片封套一样翻过去；右边是三缕交织的细波纹，随节拍摆动、向两侧流动。点一下波纹暂停，它们会慢慢平息成一条直线，再点一下继续播放；鼠标移到岛上时，岛变大一圈，封面和波纹也随之向外移一点；移到波纹上时，它会变成暂停 / 播放图标。节拍是按歌曲生成的（每首歌都不一样，同一首歌每次都一样），不是真实的音频频谱。打开「光影与色彩」时，封面会映出一圈自己颜色的光晕，波纹也用封面的颜色。暂停后停留 30 秒再收起。有歌曲在播放或暂停时，展开面板里刘海左侧（「文件」之后、AirPods 之前）会多出一个「正在播放」标签页：左边是大封面，点一下切到正在播放的 App；右边是 App 名称、歌名、歌手和专辑，一条可以点击或拖动来跳转的进度条（显示已播放和剩余时间，直播等没有时长的内容不显示），以及上一首、播放 / 暂停、下一首按钮。点一下刘海旁的封面，岛会直接展开到这个标签页，封面和波纹随之飞到标签页里的位置，收起时再飞回刘海旁，中途收起或展开也会从当前位置折返。默认只读取「音乐」和 Spotify，需要「自动化」权限（允许 Notch 控制它们）；在「设置…」的「灵动岛」页打开「读取任意 App 的正在播放」后，改用随 App 附带的第三方组件 mediaremote-adapter 读取系统「正在播放」里的任意 App（包括浏览器）。**这个开关有一定风险，打开前请先看下面的说明** |
| 🔔 通知 | 其他 App 弹出系统通知横幅时，刘海向两侧展开几秒：左边是 App 图标和名称，右边是标题和正文的第一行；上一条还没消失时来了新通知，两侧内容会模糊过渡到新的一条；鼠标移到岛上时，岛变大一圈，图标和文字也随之向外移一点。点一下左侧图标或右侧消息，岛会单独展开成这条通知的详情：左边是来源（App 图标、名称和收到的时间），右边是标题和正文全文，太长可以上下滑动；这个界面不带顶部的标签页按钮，鼠标移开后收起。有通知时，刘海右侧最外边（笔记之后）会多出一个「通知」标签页，从新到旧列出最近 30 条通知的完整内容：点一条切到对应的 App，并把它从列表里移除；右键可以删除，也可以一键全部清除。通知只保存在内存里，不写入磁盘，退出 Notch 后就没了。系统没有公开读取其他 App 通知的接口，Notch 和 boring.notch 一样，借「辅助功能」权限读取屏幕上弹出的通知横幅，所以只能看到真正弹出来的横幅：提醒样式设为「无」、被专注模式拦下的通知都看不到，系统更新改了横幅的界面结构后也可能失效。不想用可以在「设置…」的「灵动岛」页里关掉。那里还有「隐藏系统通知横幅」开关（默认关闭）：打开后，系统横幅会被移到屏幕外，只在灵动岛里显示；但横幅移走前可能会闪一下，横幅上的按钮（比如「回复」）也点不到了，要处理请从岛上打开 App；需要点按钮才会消失的提醒（比如日历的「稍后提醒」）不会被隐藏。万一 Notch 在隐藏横幅时意外退出，下次打开 Notch 时会把横幅移回原处；如果之后的横幅仍然不出现，在「终端」里运行 `killall NotificationCenter` 即可恢复 |

> [!WARNING]
> **「读取任意 App 的正在播放」是一项有一定风险的功能，默认关闭。** macOS 15.4 起，只有 Apple 签名的程序才能读取系统「正在播放」的信息。为了绕过这一限制，打开开关后 Notch 会让系统自带的 `/usr/bin/perl` 加载一个第三方预编译库 [mediaremote-adapter](https://github.com/ungive/mediaremote-adapter)（BSD 3-Clause，原样取自 boring.notch，保存在 `Vendor/MediaRemoteAdapter/`）：不属于 Apple 的代码因此以 Apple 程序的身份运行，绕开了 macOS 有意设置的隐私限制。除了它公开的源码，Notch 无法核实这个二进制库实际做了什么，而且任何一次 macOS 更新都可能让它失效。虽说市面上绝大多数的 Notch 均采用了此方法，但是这并不妨碍该方法是一种较为危险的实现。不打开它，「正在播放」仍然可以显示「音乐」和 Spotify；打开后如果这个组件在你的 Mac 上无法运行，也会自动退回到这种方式。

界面支持简体中文和英文，默认跟随系统语言；也可以在右键菜单的「设置…」里切换，切换后立即生效。「设置…」里还可以打开「登录时打开」，让 Notch 开机自动启动。

「设置…」的「通用」页里有「光影与色彩」开关（默认打开）：卡片带有自上而下的光照和细描边，天气、日历、充电、电量低、隔空投送等卡片会按内容着色，大号数字带一点光泽。展开后，岛的边缘会跟着天空变化：白天，一团柔和的光晕标出太阳此刻在天上的位置——从左侧升起，正午在底部中间，从右侧落下——越接近日出日落越橙；日落后换成月光，从右侧爬上顶部，由右往左横过（半夜有一部分藏在刘海后面），日出时从左侧下来，一天正好绕岛一圈；月亮越圆，月光越亮、越大。日出日落时间来自天气模块，会保存下来，天气暂时没有更新时也能沿用；从没取到过时，按早上 6 点日出、晚上 6 点日落来算。关掉开关就回到朴素的灰色卡片。

「通用」页最下面的「调试模式」开关（默认关闭）用来检查界面：打开后，「设置…」里多出一个「调试」页，里面按来源分组列出一些操作，点一下就能立即在刘海上显示对应的界面，必要时使用示例数据，不用等真实的通知、天气或设备出现。第一组是「灵动岛」本身：展开并保持、悬停并保持、收起并保持，以及「恢复跟随鼠标」；因为鼠标在设置窗口里，不在岛上，从这里打开的岛约一秒半后就会收起，用前三项可以让它保持原样，直到选「恢复跟随鼠标」、关闭设置窗口或关闭调试模式。之后是各个功能自己的操作，目前有计时器、日历（日程提醒）、天气、通知、正在播放、AirPods、电池、音量与亮度和文件；主页、笔记和提醒事项显示的是你自己的内容，没有调试操作。这些操作只显示示例内容，不会改动你的笔记、提醒事项、日历、文件架里的文件或任何设置，也不会去控制系统音量、亮度或其他 App。关掉开关，「调试」页就会消失。

更多功能见下面的 [路线图](#路线图)。

## 系统要求

- **macOS 26 或更新版本**（界面用到了 macOS 26 的 Liquid Glass 效果）
- **带刘海的 MacBook**（Apple Silicon）。没有刘海的屏幕上会显示一个模拟刘海。

## 安装（给朋友用）

到 [Releases](https://github.com/HyperspaceFT/Notch/releases) 页面下载最新的 `Notch-x.y.z.zip`，然后：

1. 解压，把 `Notch.app` 拖进「应用程序」文件夹；
2. 双击打开。因为 App 没有经过苹果公证，系统会拦截并提示「无法验证开发者」，点「完成」；
3. 打开 **系统设置 → 隐私与安全性**，拉到最下面，点 **「仍要打开」** 并输入密码。之后就能正常使用了；
4. 第一次打开时系统会请求「辅助功能」权限（用来接管音量键和亮度键，以及在灵动岛里显示通知），点「打开系统设置」，在列表里打开 Notch；还会请求「蓝牙」权限（用来显示 AirPods 的连接和电量），点「允许」。第一次展开刘海时会请求「定位」权限（用来显示当地天气）和「日历」权限（用来显示「日历」App 里的日程），点「允许」。「提醒事项」权限要等第一次在提醒事项卡片上点「允许」时才会请求。Notch 第一次读取「音乐」或 Spotify 时，系统会询问是否允许 Notch 控制它们（「自动化」权限，用来读取正在播放的歌曲和暂停 / 播放），点「允许」。

也可以在终端里执行下面这条命令，去掉下载隔离标记后直接打开：

```bash
xattr -dr com.apple.quarantine /Applications/Notch.app
```

更新到新版本后，如果音量和亮度提示又变回了系统自带的样式，或者通知不再出现在灵动岛里，到 **系统设置 → 隐私与安全性 → 辅助功能** 里选中 Notch，点「−」删掉，再重新打开 Notch 允许一次。App 没有经过苹果的正式签名，签名变了的新版本会被系统当成另一个 App。

退出方法：鼠标移到刘海上，等它变大一圈后点右键，选 **退出**（英文界面下是 Quit）。

## 从源码构建

**不需要安装 Xcode**，只要有命令行工具（Command Line Tools）即可：

```bash
xcode-select --install
```

然后：

```bash
git clone https://github.com/HyperspaceFT/Notch.git
cd Notch
make run
```

构建好的 App 在 `build/Notch.app`，可以直接双击运行。建议先执行一次 `make cert` 创建本地签名证书，否则每次重新构建后「辅助功能」权限都要重新给，见下面的 [本地签名证书](#本地签名证书)。

常用命令：

| 命令 | 作用 |
|---|---|
| `make build` | 构建 Release 版，输出到 `build/Notch.app` |
| `make debug` | 构建 Debug 版 |
| `make run` | 构建并（重新）启动 App |
| `make test` | 运行单元测试 |
| `make dist` | 打包成 `build/dist/Notch-<版本号>.zip`，方便发给别人 |
| `make clean` | 删除所有构建产物 |
| `make cert` | 创建本地签名证书，让重新构建后「辅助功能」权限不失效 |

调试时可以强制刘海停在某个状态，方便看效果；加上 `-NotchDebugSnapshot` 还能把界面导出成图片（不需要屏幕录制权限，但导出的图里没有 Liquid Glass 效果）：

```bash
open build/Notch.app --args -NotchDebugState expanded   # 也可以是 activity / collapsed
open build/Notch.app --args -NotchDebugState expanded -NotchDebugSnapshot /tmp/notch.png
```

### 本地签名证书

默认情况下，构建出来的 App 只有临时签名（ad-hoc），每次构建的签名都不一样。系统会把每次构建出来的 App 当成一个新 App，之前在「辅助功能」里给的权限就失效了，得删掉再重新允许。

在钥匙串里建一个本地签名证书，之后的构建都用它签名，签名就不会再变，权限也会一直保留。只需要执行一次：

```bash
make cert
```

它会：

1. 生成一个名为「Notch Local Signing」的自签名代码签名证书，有效期 10 年；
2. 把证书和私钥导入「登录」钥匙串，并允许 `codesign` 直接使用，构建时不会弹窗询问。

之后 `make build`、`make debug`、`make run` 都会自动用这个证书签名，构建输出里会显示 `==> Signing (Notch Local Signing)`；钥匙串里找不到它时会退回临时签名，显示 `==> Signing (ad-hoc; …)`。

这个证书只用来在本机给 Notch 签名。它是自签名的，「钥匙串访问」会把它标成「此证书不受信任」，这不影响签名，不需要改信任设置。

换成证书签名后第一次运行时，需要最后一次到 **系统设置 → 隐私与安全性 → 辅助功能** 里把旧的 Notch 删掉（−）再重新允许；以后再重新构建就不用管了。

不想用了：打开「钥匙串访问」，在「登录」钥匙串的「我的证书」里删掉「Notch Local Signing」，之后的构建会回到临时签名。

## 项目结构

项目是一个 Swift Package，按「外壳 + 可插拔功能」拆成几个模块，依赖方向是单向的：

```
Sources/
├── NotchKit/        # 功能模块的「接口」：NotchFeature 协议、NotchActivity、NotchContext、主页模块、右键菜单项、界面语言
├── NotchUI/         # 设计系统：刘海形状、主题、动画、Liquid Glass 按钮等通用组件
├── NotchShell/      # 外壳：窗口、屏幕/刘海定位、鼠标悬停、状态机、根视图
├── Features/        # 各个功能，每个功能一个文件夹，只依赖 NotchKit + NotchUI
│   ├── Battery/
│   ├── Calendar/
│   ├── Clock/
│   ├── Files/
│   ├── Home/
│   ├── Notes/
│   ├── Notifications/
│   ├── NowPlaying/
│   ├── Reminders/
│   ├── SystemHUD/
│   └── Weather/
└── NotchApp/        # 可执行入口、设置窗口；FeatureCatalog.swift 是启用功能的唯一清单
Tests/               # 单元测试
Resources/Info.plist # App 信息模板
scripts/             # 构建、运行、打包脚本
Vendor/              # 随 App 附带的第三方预编译组件（mediaremote-adapter，BSD 3-Clause）
VERSION              # 版本号
```

```
NotchApp ──▶ NotchShell ──▶ NotchKit
    │            └────────▶ NotchUI
    └──▶ Features/* ──▶ NotchKit + NotchUI
```

刘海有三种状态：

- **collapsed**：和硬件刘海一样大，看不出来；
- **activity**：某个功能发出「实时活动」时，刘海向两侧延伸，左右显示内容（比如充电提示）；
- **expanded**：点击刘海后展开，顶部是各功能的标签页（主页、文件、AirPods（连接时才出现）在刘海左侧，计时器（计时时才出现）、电池、笔记和通知（有通知时才出现）在右侧），下面是当前功能的内容。

鼠标停在 collapsed 或 activity 状态的刘海上时，刘海会带一点回弹地放大一圈（hovered），下方两个圆角也随之放大，和原来的圆角同心；这时点击展开，右键弹出菜单（「计时器」、「设置…」和「退出」）。

## 添加新功能

新增一个功能只需要三步：

1. 在 `Sources/Features/<名字>/` 下新建文件夹，写一个遵循 `NotchFeature` 的类；
2. 在 `Package.swift` 的 `featureNames` 数组里加上 `"<名字>"`，会自动生成 `<名字>Feature` 模块并接进 App；
3. 在 `Sources/NotchApp/FeatureCatalog.swift` 里 `import <名字>Feature`，并把实例加进列表。列表顺序就是展开面板里标签页的顺序；标签页默认在刘海左侧，把 `tabPlacement` 设为 `.trailing` 可以放到右侧；`isTabAvailable` 返回 `false` 时标签页暂时隐藏（比如 AirPods 没连接时）。

功能可以通过 `NotchContext` 和外壳交互，比如 `present(_:)` 发出一个实时活动、`dismiss(activityID:)` 收回它；`requestExpand(detail:)` 可以让岛单独展开成某个视图，不带顶部的标签页按钮（比如通知的详情）。具体写法可以参照 `Sources/Features/Battery`。

功能还可以实现 `makeHomeModules()`，为主页提供模块（`NotchHomeModule`），并用 `HomeModuleSizing` 写明它的最小 / 最大长度，或者长度固定；用户就能在「设置…」的「主页」页里把它放到主页上。具体写法可以参照 `Sources/Features/Weather`。功能的标签页需要更宽时，可以通过 `expandedWidth` 给出展开后的宽度（520–880 点），主页就是这样跟着模块变宽的。

功能还可以通过 `menuItems` 往刘海的右键菜单里加菜单项（`NotchMenuItem`，可以是按钮、子菜单或分隔线），显示在「设置…」上面，并且可以随功能的状态变化。具体写法可以参照 `Sources/Features/Clock`。

功能还可以通过 `debugItems`（同样是 `NotchMenuItem`）往「设置…」的「调试」页里加操作，只在「通用」页打开「调试模式」后才会显示。每个操作用示例数据立即显示功能的某个界面，方便检查样子；它们不能改动用户自己的数据，也不能去控制系统或其他 App。和 `menuItems` 一样，在页面绘制时读取。内容是用户自己数据的功能（主页、笔记、提醒事项）不需要提供。

界面文字用 `localized(en:zh:)` 同时写出英文和中文，并在视图绘制时读取（比如 `title` 写成计算属性），这样切换语言后会立即刷新。
